How I take a partner from first call to go-live

I've run enough of these to have a routine. It goes roughly like this.

  1. First, I look for where the partner breaks our pattern.

    Every partner does, somewhere. The mail-order pharmacy broke ours in three places. They start the flow instead of us. They reject any order without a valid NDC. And they needed an on-hold state we had to build from scratch.

  2. Then I map every event, start to finish.

    Prescription approved, received, matched, ordered, shipped. I write out each message and what it changes. Engineers get one picture of where patients get matched, where orders get created, and which events move a status.

  3. I decide how it fails before it fails.

    Webhook validation, duplicate events, an unmatched patient, an alert for the ops team. All of it goes in the PRD. On the forms project we swapped a flat 30-second retry for jittered retries to stop silent submission failures.

  4. When we replace a vendor, both systems run side by side.

    For the Zoho Desk exit, every task got written to both. We migrated about a million events, reconciled them daily, and ran a parallel week before planning the switch-off.

  5. Last, we test in production, together.

    I write the launch plan. We place and cancel real test orders with the customer and API teams. Stakeholders get a status note from me every day until it's live.

The calls behind the work

A lot of my job is choosing between two reasonable options and owning the result. Here are five recent ones.

How should we identify a drug?RxCUI

NDC looks like the obvious key, until you notice one drug has many NDCs and the formats differ by source. RxCUI gives each drug concept one stable ID. So five separate medication lookups are moving onto one compendia service built on it.

Call RxNav's API, or host RxNorm ourselves?Host it

RxNav caps out at 20 requests a second. That's fine for a demo and too slow for a pharmacy. We load RxNorm as flat files and keep Medi-Span for the two things nothing else gives us: therapeutic class and DEA schedule. The license now covers what we actually use.

What if a prior authorization vendor can't cover a payer?Fall back

The new vendor goes first. If it comes back with no coverage, the request moves to CoverMyMeds. If a payer has no electronic question set, the request goes to fax after a set window. Between the two vendors we reach more than 85% of pharmacy-benefit payers.

How do you leave a vendor without losing data?Run both

Write to both systems, reconcile every day, and plan the switch-off once the numbers match. That's how we're moving about a million task events off Zoho Desk.

How do you build for a federal deadline?One library

CMS-0057-F brings a compliance deadline in January 2027. I planned one NCPDP library for prior authorization, real-time benefit checks, and formulary. The message builders stay vendor-neutral. Only the transport layer knows who's on the other end, so each new vendor costs less to add.

Finding 15,800 settlements a campaign missed

A polio campaign only works if it reaches every child. When I picked up the Geographic Coverage Support System in 2022, supervisors spent about six hours after each campaign working out which settlements no team had reached.

With WHO, NEOC, and the Gates Foundation, we digitized boundaries for 6,000+ administrative areas and put 69,000+ vaccinators on a live map. Then we built missed-settlement detection, geospatial QA, and dashboards for supervisors. Later we added an ML model that reads GPS traces to find where each team starts its day.

The review now takes under 30 minutes. The system flagged 15,800+ unvaccinated settlements, and follow-up campaigns reached 5,000+ children in them. WHO adopted it to monitor polio campaigns.

Building for polio teams

Most of this work happened with WHO, the Gates Foundation, and Pakistan's National Emergency Operations Centre. Vaccinators and supervisors use these tools in the field, often with weak signal, so the apps work offline first.

  • Vaccinators used to count on paper tally sheets. DISP moves that count onto offline-first Android and web apps, with checks built in for supervisors.

    • I ran user research with vaccinators, area in-charges, and union council medical officers.
    • We piloted in the field and reshaped the backlog after each round.
    • Pilot districts saw data timeliness and accuracy improve by over 40%.
    • It's now scaling to a national rollout.

  • Vaccine carriers that report on themselves. Sensors log temperature, location, and every time the lid opens. A dashboard shows breaches as they happen.

    • I wrote the sensor specification and ran pilots with NEOC, DEOC Islamabad, and EPI Balochistan.
    • The pilots caught several cold chain breaches early enough to fix them.
    • I wrote the proposal to roll out 180 devices across 36 districts.

  • Where does a vaccination team actually start its day? An ML model reads GPS traces and finds out.

    • I worked with data scientists on detecting when teams arrive and leave.
    • I designed geofencing that timestamps every arrival and departure.
    • We compared detected centres with declared ones. The gap showed where reporting was off.
    • The model became a core part of GCSS.

  • Getting WHO's family planning digital adaptation kit to talk to Sindh's client record and EMR systems.

    • I defined the FHIR exchange for family planning encounters and client records.
    • We aligned data dictionaries and clinical terms with the health department.
    • I planned pilots and integration tests across selected facilities.

  • When a sewage sample tests positive, where did the virus come from? This GIS pilot traced catchments upstream, which helped authorities place sampling sites and aim their outbreak response.

  • I audited how data moves through WHO's integrated data system and specified fixes for how it talks to partner systems.

  • A side trip into agriculture. AgriTech startups use xLATS to run field operations, onboard farmers, and keep their farm maps in one place.
