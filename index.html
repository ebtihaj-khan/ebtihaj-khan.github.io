How I run an integration

Every partner integration follows the same five steps. Each example comes from a shipped project.

  1. Find where the partner breaks our pattern

    A new partner rarely fits the existing model. For the mail-order pharmacy, I found three breaks: the partner starts the flow, it rejects orders without a valid NDC, and it needs a new on-hold state.

  2. Map every event, end to end

    I write out each message from prescription approval to shipment. The map shows engineering where to match patients, where to create orders, and which events update status.

  3. Specify how it fails

    Webhook validation, idempotency, match failures, and ops alerts go into the PRD. For the forms service, jittered retries replaced a flat 30-second retry so failed submissions surface.

  4. Prove parity before cutover

    When we replace a vendor, both systems run side by side. Daily reconciliation shows the data matches before the old system goes away.

  5. Run launch readiness in production

    I write the launch plan, run place and cancel tests in production with the partner, and send stakeholders a daily status update until go-live.

Calls I made, and why

A product manager's work shows in decisions. Here are five from the last year.

Which key identifies a drug?RxCUI

One drug maps to many NDCs, and NDC formats differ between sources. RxCUI gives one stable ID per concept. Five separate medication lookups move to one compendia service on that key.

Call RxNav, or host RxNorm?Host it

The RxNav API caps at 20 requests a second. Platform volume needs more. We load RxNorm as flat files and keep Medi-Span for the two fields nothing else supplies: therapeutic class and DEA schedule. That cut the licensed scope to what we use.

What happens when a prior authorization vendor has no coverage?Fall back

The new vendor goes first. On a no-coverage response, the request moves to CoverMyMeds. Payers without an electronic question set go to fax after a set window. Together the two vendors cover more than 85% of pharmacy-benefit payers.

How do we leave a vendor without losing data?Run both

For the Zoho Desk exit, the platform wrote every task to both systems. We migrated about 1M events and reconciled them daily. Cutover follows a one-week parallel run with a subset of users.

How do we build for a federal deadline?One library

CMS-0057-F brings a January 2027 compliance deadline. I planned one NCPDP library for prior authorization, RTPB, and formulary. Message builders hold no vendor logic. Only the transport client knows the vendor, so the next vendor costs less.

Case study: finding the children a campaign missed

The Geographic Coverage Support System, built with WHO, NEOC, and the Gates Foundation from 2022 to 2024.

Problem
A polio campaign must reach every child. Supervisors could not see which settlements a team never reached. A review to find missed settlements took about six hours.
Users
69,000+ vaccinators, their supervisors, and WHO and NEOC campaign managers.
What I shipped
Digital boundaries for 6,000+ administrative areas, live team tracking, missed-settlement detection with geospatial QA, and supervisor dashboards. Later, an ML module that finds where teams start each day.
Result
The system found 15,800+ unvaccinated settlements. Follow-up campaigns vaccinated 5,000+ children there. WHO adopted it for polio campaign monitoring.
